# AI Code Explosion Demos

Demo apps for the AI Code Explosion presentation. Every app here is generated by
pointing a coding agent at one of the prompts in this directory, so the same
requirements can be built again and again across different agent harnesses and
models and the results compared side by side.

## Repo contents

| File | What it is |
| --- | --- |
| `BRD.md` | The requirements every demo is built from. |
| `java-prompt.txt` | Build the app in plain Java. |
| `jakarta-ee-prompt.txt` | Build the app with OpenLiberty and Jakarta EE. |
| `demo-prompt-common.md` | The instructions every prompt shares. |
| `AGENTS.md` | The coding conventions agents follow. `CLAUDE.md` links to it. |

Each prompt is only three lines: the stack to build, the project name prefix to
use, and a pointer to `demo-prompt-common.md` for everything else. That keeps the
shared rules in one place, so a change to the naming scheme or to what the
README must record lands in every prompt at once.

## Prerequisites

`cloc` has to be installed, because the prompts require the line counts in the
generated README to come from it:

| Platform | Command |
| --- | --- |
| macOS | `brew install cloc` |
| Debian, Ubuntu | `sudo apt install cloc` |
| Fedora, RHEL | `sudo dnf install cloc` |
| Arch | `sudo pacman -S cloc` |
| Alpine | `sudo apk add cloc` |
| Windows | `choco install cloc` or `scoop install cloc` |

Where none of those fit, `npm install -g cloc` works on any platform with Node
installed. There is a `winget install AlDanial.Cloc` package too, but cloc's own
documentation warns it may not work, so prefer Chocolatey or Scoop on Windows.

Verify that installtion was successful prior to running a prompt:

```bash
cloc --version
```

Building and running a generated app requires a JDK and Maven. Which JDK depends on
what the agent chose, so check the app's own README. (AGENTS.md specifies at least JDK 25.)

## How to run a prompt

Start your agent in the root of this repository and ask it to run the prompt you
want. For example:

```
Run the prompt java-prompt.txt
```

Nothing needs to be set up first. The agent reads the prompt, follows it into
`demo-prompt-common.md`, works out the project name, and builds the app in a new
directory of its own.

Run it from the root, not from inside a demo directory. The prompts resolve
`BRD.md` and `demo-prompt-common.md` as siblings, and the next project name is
worked out by looking at the demo directories already here.

## The generated apps

Each app lives in a directory named
`[stack]-demo-[agent harness]-[model]-xx`, so
`java-demo-claude-code-opus-5-1` is the first plain Java demo built by Claude
Code using Claude Opus 5. The suffix counts up per combination of stack,
harness, and model.

Every directory carries copies of `BRD.md` and the prompt files it was built
from, so each app records the exact requirements and instructions that produced
it even after those files change here. Its own `README.md` has the build and run
commands, along with the date, harness, model, and line counts.
